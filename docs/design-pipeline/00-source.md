것 외에는 아직 아무것도 확정되지 않았다.

## 영상이 설명하는 워크플로

1. **Pinterest 무드보드.** 원하는 레퍼런스를 모아 무드를 고정한다.
   디자이너가 원래 하는 방식과 같다.
2. **paper.design 셰이더와 디더링.** 정지 이미지로 끝내지 않고 효과를
   고른다.
3. **디자인 철학을 녹음해 `soul.md`로 만든다.** 제품의 정체성, 목표,
   대상 사용자, 주고 싶은 느낌과 경험을 말로 논의하고 녹음한 뒤 그것을
   `soul.md`로 정리한다. **철학은 사람이 준다.**
4. **시안을 N개 생성한다.** 목업이 아니라 **동작하는 인터랙티브 HTML
   페이지**로 뽑는다. 영상은 이 점을 강조한다. Figma 목업으로는 호버와
   전환을 전달할 수 없었다.
5. **랭킹 시스템도 같이 만들게 한다.** 별점과 코멘트를 남기고 취합해
   올리고 내린다.
6. **라운드를 반복한다.** 영상 제작자는 6라운드를 이틀에 돌렸다.
7. **모델 간 블라인드 비교.** A/B/C를 가려놓고 "AI 느낌"이 나는지 본다.

## 영상의 핵심 주장

> 디자인을 잘하려면 많이 보고 **선별**을 잘해야 한다.

도구는 이미 충분히 좋아졌고 병목은 사람의 보는 눈으로 옮겨갔다는
주장이다. 영상은 이 evaluation 문제가 RLVR로 풀리지 않는 이유까지
다룬다. "AI 느낌"으로 지목된 표식은 보라색, 그라데이션, 관성적으로
붙는 장식이다.

## Forma에 이미 있는 것

이 제안은 새 기능이 아니라 **이미 있는 기계의 빈 절반**에 해당한다.

`src/qa/candidates.ts`가 후보를 만들고 채점하고 승자를 뽑는다. 축을
렌더러에 연결한 뒤 실제로 서로 다른 후보 8개가 나온다. 그런데
`examples/dashboard`에 기록된 실측대로, **결함이 없는 후보는 모두 100점
동률**이다. soft score가 lint finding의 감점만 계산하므로 깨끗한 후보
사이의 선호를 가르지 못한다.

영상의 주장과 forma의 부채가 같은 지점을 가리킨다. 생성은 되고 선별이
안 된다.

## 정면으로 충돌하는 제약

**이 충돌을 판단하는 것이 1단계 조사의 핵심이다. 조사자가 임의로
한쪽을 택하지 말고 선택지와 대가를 같이 제시하라.**

`CLAUDE.md`와 `docs/security.md`에 적힌 절대 제약:

- 에이전트는 HTML/CSS를 직접 생성하지 않는다. `forma.spec.json`만 쓴다
- 외부 LLM API 호출 금지
- 문서 내용을 제3자 네트워크 엔드포인트로 전송 금지
- 렌더된 산출물의 외부 네트워크 요청 **0건**

제안된 워크플로는 이 셋 모두와 부딪친다. 에이전트가 인터랙티브 HTML을
직접 만들고, Pinterest와 paper.design은 외부 서비스다.

생각해볼 구분 하나: **저작 시점과 렌더 시점은 다르다.** 무드보드 수집과
`DESIGN.md` / `SOUL.md` 작성이 저작 시점의 입력이고, 그 결과가 문서마다
새 HTML이 아니라 **결정론적 렌더러의 토큰과 컴포지션 축**으로 내려간다면
제약을 지키면서 영상의 방법을 쓸 수 있을지도 모른다. 이것이 유일한 답이라는
뜻은 아니다. 다른 구조가 더 나을 수 있고, 제약 자체를 바꾸는 것이 맞다는
결론도 가능하다. 다만 제약을 바꾸자는 결론이라면 무엇을 잃는지 명시하라.
