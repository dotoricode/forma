# SOUL과 DESIGN 작성에 필요한 답변 (오케스트레이터가 대신 작성)

사용자가 이 답변을 오케스트레이터에게 위임했다. 그런데 2단계 조사의 결론은
"철학은 사람이 준다"였다. 대신 답하면 그 전제가 깨진다.

그래서 **취향을 지어내지 않았다.** 저장소에 이미 있는 증거에서 역추출했고,
그것이 2단계 권고와 같은 방법이다. 말보다 이미 만든 것을 먼저 본다.

각 항목에 표시를 달았다.

- **[증거]** — 저장소의 파일·코드·커밋에서 확인했다. 파일을 댔다.
- **[판단]** — 증거에서 끌어낸 추론이다. 틀릴 수 있고 뒤집어도 된다.
- **[공백]** — 증거가 없다. 사람이 답해야 한다.

**[판단]과 [공백]은 사용자가 뒤집으라고 표시한 것이다.** 그대로 두면 내
추론이 사용자의 철학으로 굳는다.

---

## 0. 이 문서가 답하는 질문

2단계 조사가 제안한 인터뷰 항목이다. 대상 제품은 forma 자신이다. 첫 사용자가
forma이고, 파이프라인을 도그푸딩할 대상도 forma다.

---

## 1. 제품 정체성

**무엇인가** — 복잡한 작업물을 읽고 무엇을 말해야 할지 정한 다음, 검증 가능한
spec을 써서 결정론적 렌더러가 오프라인 HTML 한 장으로 컴파일하게 하는 도구.
**[증거]** `README.md`, `skills-src/forma/skill.json`

**누구를 위한 것인가** — 내부 기술 자료를 다루는 엔지니어링 조직.
문서를 받는 쪽은 그 자료의 이해관계자다.
**[증거]** 기본 `confidentiality`가 `internal`이고 fixture 대부분이 사내
릴리스 판단이다. `fixtures/*/forma.spec.json`

**무엇을 우선하는가** — 재현성과 검증 가능성. 표현의 자유는 그 아래다.
**[증거]** `examples/report/forma.spec.json`의 decision-matrix가 재현성·통제에
가중치 3, 자유도에 1을 준다. 그 문서 본문이 "이 가중치가 결론을 사실상
정한다"고 스스로 적고 있다.

---

## 2. 트레이드오프 (제품이 무엇을 포기했는가)

이걸 적는 이유는, 포기한 것을 적지 않은 철학 문서는 모든 것을 잘한다고
주장하게 되기 때문이다.

| 포기한 것 | 얻은 것 | 근거 |
|---|---|---|
| 표현의 자유. 블록 어휘에 없는 것은 만들 수 없다 | 같은 spec이 같은 HTML을 낸다 | **[증거]** `examples/report` finding-cost |
| 즉시성. 블록이 없으면 블록부터 추가해야 한다 | 품질 규칙을 검증기와 lint로 고정 | **[증거]** `src/spec/validate.ts` |
| 산출물 크기. 문서가 짧아도 CSS 전체가 실린다 | 외부 요청 0건, `file://`로 열림 | **[증거]** dashboard 산출물 CSS 34.7% 실측 |
| 개인화. 지금은 모든 문서가 같은 CSS를 받는다 | — (이건 얻은 게 없는 순손실이다) | **[증거]** 1단계 "통로 부재" |

마지막 줄이 이번 파이프라인이 고치려는 것이다.

## 3. SOUL: 뒤집을 수 있는 문장만

2단계 권고를 따랐다. 뒤집었을 때 **누군가는 반대할 문장**만 넣는다.
"읽기 좋아야 한다" 같은 문장은 뒤집으면 아무도 지지하지 않으므로 뺐다.
그런 문장은 비용만 늘린다. 이 판단은 arXiv:2602.11988이 뒷받침한다 —
컨텍스트 파일의 **지시**는 에이전트가 따르지만 **개요 산문**은 성공률을
올리지 않고 추론 비용만 20% 넘게 늘린다. 확인함(초록).

1. **완결된 문장이 라벨보다 낫다.** 섹션 제목은 "개요"가 아니라 주장이어야
   한다. 뒤집으면: 제목은 짧은 라벨이어야 스캔하기 쉽다. 실제로 반대하는
   사람이 있다. **[증거]** `DESIGN.md` layout grammar
2. **근거 없는 단정은 렌더 전에 막는다.** 편의보다 정직을 택한다. 뒤집으면:
   저자를 믿고 통과시킨다. **[증거]** `verified-claim-without-evidence`
3. **모르는 것은 문서에 적는다.** `stillUnknown`과 `knownGaps`가 비어 있는
   문서를 의심한다. 뒤집으면: 미확인 항목은 독자를 불안하게 하므로 뺀다.
   **[증거]** `src/blocks/advanced.tsx`의 brief, dashboard의 data-freshness 강제
4. **반대 의견은 기록한다.** 사유를 남기지 않고 반대한 사람도 기록한다.
   뒤집으면: 합의된 결정만 적어야 실행이 빠르다. **[증거]**
   `src/room/freeze.ts`의 `UNSTATED_OBJECTION`
5. **장식은 의미가 있을 때만 쓴다.** 색은 상태나 데이터 계열을 뜻할 때만
   쓴다. 뒤집으면: 시각적 흥미를 위해 색을 쓴다. **[증거]** `DESIGN.md` 토큰 절
6. **한 번에 다 보여주기보다 순서를 정한다.** 결론을 먼저, 근거를 뒤에.
   뒤집으면: 독자가 스스로 판단하게 재료를 균등하게 편다. **[증거]**
   `skills-src/forma/references/artifacts/report.md`

**[공백]** 여기 없는 것 중 사용자만 답할 수 있는 것: 이 문서를 받는 사람이
읽고 나서 무엇을 느끼기를 바라는가. 위 6개는 전부 "무엇을 하는가"이지
"어떤 느낌인가"가 아니다. 영상에서 가장 큰 비중을 차지한 부분이 이쪽인데
저장소에는 증거가 없다.

## 4. 반례: "이건 싫다"

3단계 조사가 진행 중이지만, 2단계 결론대로 이게 가장 값싸고 신뢰도 높은
신호다. 그리고 **forma는 이미 이 목록을 갖고 있다.** 새로 만들 것이 아니라
있는 것을 확인하는 일이다.

**[증거]** 기계가 집행하는 반례 17종:

- `design-lint.ts` 9종 — bracket-border, centered-width-cap, ch-measure,
  decorative-glyph-content, gradient-overuse, hardcoded-paint-color,
  oklch-color-mix-hue-shift, rounded-edge-border, thick-side-border
- `dom-lint.ts` 8종 — card-saturation, false-interactivity,
  layout-repetition, nested-surface, orphan-heading, pill-overuse,
  prose-run, verified-claim-without-evidence

**[증거]** 사람이 봐야 하는 반례는 `generic-ai-patterns.md`에 있다. 보라색
그라데이션 히어로, 글래스모피즘, 모든 것을 둥근 카드로 감싸기, 의미 없는
pill, SaaS 랜딩 히어로와 큰 CTA, 장식용 `{ }`, 순차 fade-up, hover-lift.

**[판단]** 이번 세션에서 육안 검수로 잡은 것들도 반례에 들어갈 자격이 있다.
전부 게이트를 통과한 뒤에 눈으로 찾은 것들이다.

- 라벨 없는 숫자 나열 ("1 / 1 / 0")
- 데크와 본문이 같은 톤이라 위계가 안 읽힘
- 구분선이 섹션 끝에 있어 제목이 떠 있음
- 넓은 화면에서 한쪽에 붙고 반대편이 비어 미완성으로 읽힘
- 기록에 변수명이 그대로 노출 (`delayDays=30`)

## 5. 철학에서 실제로 연역되는 시각 규칙

2단계의 핵심 발견은 **철학에서 나오는 시각 규칙이 극소수**라는 것이었다.
영상 사례에서도 soul.md가 정한 규칙은 하나뿐이었고 바우하우스는 선별에서
나왔다. 그러니 여기를 억지로 채우면 안 된다.

정직하게 세어보면 위 6개 중 시각 규칙으로 내려가는 것은 둘이다.

- 5번(장식은 의미가 있을 때만) → 색 사용 정책, 표면 단계 3개 제한
- 1번(라벨보다 문장) → 제목 조판, 측정 폭

나머지 넷은 **내용 규칙**이고 렌더러가 아니라 검증기와 스킬이 집행한다.
이 구분이 프로필 스키마 설계에 직접 들어가야 한다. 프로필에는 5번과 1번에서
나온 것만 담고, 나머지를 담으려는 시도는 하지 않는다.

**[판단]** 그래서 나머지는 선별로 정한다. 이게 4단계에서 후보가 실제로
갈리게 만들어야 하는 이유다.

## 6. 강제 선택 (증거가 한쪽을 지지하는 것만)

2단계가 권한 A/B 방식이다. 증거가 없으면 답하지 않고 [공백]으로 뒀다.

| 질문 | 선택 | 근거 |
|---|---|---|
| 밀도: 여백이 넉넉한가, 정보가 빽빽한가 | artifact에 따라 다르다. dashboard는 compact, 나머지는 comfortable | **[증거]** fixture meta |
| 색: 무채색 기조 + 강조 하나인가, 다색인가 | 무채색 기조. 색은 상태와 데이터 계열에만 | **[증거]** `DESIGN.md` |
| 서체: 한 계열인가, 대비되는 페어링인가 | 한 계열(Geist + Plex Sans KR)에 mono 보조 | **[증거]** `DESIGN.md` |
| 모서리: 각진가, 둥근가 | 기능적 최소 라운딩. "모두 pill"은 반례 | **[증거]** `DESIGN.md`, `pill-overuse` |
| 모션: 있는가, 없는가 | 최소. 120/180/240ms, reduced-motion에서 전부 제거 | **[증거]** `DESIGN.md` |
| 텍스처/그레인: 쓰는가 | 안 쓴다 | **[판단]** 금지 목록에 명시는 없지만 "장식 효과가 아니라 컴포지션으로 구분한다"는 의도와 충돌 |
| 다크 모드: 동등한 1급인가, 라이트 우선인가 | 동등. 두 모드 모두 QA 대상 | **[증거]** `qa/dark-1440.png` |
| 표지: 큰 커버가 있는가 | artifact마다 다르다. dashboard는 긴 커버 없음 | **[증거]** `design-grammar.md` |
| 이미지: 문서에 래스터 이미지를 넣는가 | 안 넣는다 (현재 블록 자체가 없다) | **[증거]** 1단계 claude |
| **읽는 사람이 받아야 할 인상** | — | **[공백]** 사용자만 답할 수 있다 |
| **경쟁/참조 대상으로 삼고 싶은 문서** | — | **[공백]** 이번 세션에서 DocPilot 하나를 비교 대상으로 썼지만 그건 사용자가 그때 지정한 것이지 지속적 기준인지는 모른다 |

## 7. 파일 배치와 이름 충돌

**[증거]** 1단계와 2단계가 모두 지적했다. 제안된 `DESIGN.md`는 루트
`DESIGN.md`와 이름이 겹치고, 루트 쪽은 forma 렌더러 자신의 시각 언어
원천이다.

**[판단]** 정리하면 이렇다.

| 파일 | 소유 | 무엇 | 누가 읽나 |
|---|---|---|---|
| `DESIGN.md` (루트) | forma | 렌더러의 시각 언어. 지금 그대로 둔다 | 기여자, 에이전트 |
| `.forma/soul.md` | 사용자 프로젝트 | 제품 철학. 뒤집을 수 있는 문장만, 짧게 | 사람, 에이전트 |
| `.forma/design.tokens.json` | 사용자 프로젝트 | 기계용 시각 결정. 스키마 검증 | 렌더러 |
| `.forma/dislikes.md` | 사용자 프로젝트 | 반례 | 사람, 에이전트 |

산문과 기계 입력을 갈라놓는 것이 요점이다. 산문은 렌더러가 읽지 않는다.

**[공백]** `.forma/`가 맞는 위치인지는 확인하지 않았다. 두 조사가 같은
제안을 했지만 둘 다 제안이지 검증이 아니다.

## 8. 이 문서의 한계

**가장 큰 공백은 6번 표의 마지막 두 줄이다.** 제품이 어떤 인상을 줘야
하는지, 무엇을 닮고 싶은지 — 영상에서 가장 큰 비중을 차지한 부분이고
저장소에 증거가 전혀 없는 부분이다. 나는 이것을 지어내지 않았다.

역추출로 얻은 것은 **forma가 지금까지 무엇을 해왔는가**이지 **앞으로
무엇이고 싶은가**가 아니다. 전자는 관성이고 후자는 의도다. 이 문서만으로
SOUL을 확정하면 forma는 지금 모습에 갇힌다.
