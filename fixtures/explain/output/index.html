initialize() 호출부터 정책 캐시 갱신까지, 실제로 어떤 순서로 일어나는가

  • Kotlin
  • Android SDK
  • 합성 예제

앱이 시작될 때 SDK는 서버 정책을 어떤 순서로 확인하고, 실패하면 무엇을 하는가?

SDK는 로컬 캐시를 먼저 신뢰하고, 백그라운드에서 서버 정책을 갱신하며, 서버가 응답하지 않으면 마지막으로 확인된 정책으로 안전하게 동작을 계속한다.

  • 초기화는 항상 로컬 캐시 정책으로 즉시 완료된다. 네트워크를 기다리지 않는다.
  • 서버 정책 갱신은 백그라운드 태스크이며 실패해도 앱 시작을 막지 않는다.
  • 정책이 90일 넘게 갱신되지 않으면 SDK는 스스로 기능을 축소한다.

핵심 3가지

  1. initialize()는 네트워크 응답을 기다리지 않고 즉시 반환한다.
  2. 정책 갱신은 별도 백그라운드 태스크에서 최대 3회 재시도한다.
  3. 정책이 오래되면(90일+) SDK는 기능을 축소하되 크래시하지 않는다.

용어 정리

conservativeDefault
서버 정책을 한 번도 받지 못했을 때 사용하는, 가장 제한적인 안전 기본값.
backoffFor(attempt)
재시도 간격을 지수적으로 늘리는 함수. 서버 부하를 줄이기 위한 설계다.
