Forma 첫 문서 만들기

설치부터 첫 HTML까지

Forma로 첫 문서를 어떻게 만드나?

설치하고, 스펙을 하나 만들고, 렌더한다. 세 단계면 브라우저에서 열리는 단일 HTML이 나온다.

  • HTML을 직접 쓰지 않는다. forma.spec.json만 쓴다
  • 렌더된 파일은 네트워크 요청을 하지 않아서 file://로 열어도 그대로 동작한다
  • 검증이 먼저다. 스펙이 계약을 어기면 렌더 전에 막힌다

이 문서로 끝낼 수 있는 것

  • Forma를 로컬에 설치한다
  • 유효한 forma.spec.json을 하나 만든다
  • 단일 HTML로 렌더해서 브라우저로 연다

예상 소요: 10분

적용 대상

해당됨

  • Node 20.19 이상
  • pnpm 사용 환경
  • macOS / Linux / Windows

다루지 않음

  • Agent Skill 설치와 호출 (별도 문서)
  • Decision Room 실행
  • 사내 CI 연동

시작하기 전에

  • Node 20.19 이상node --version
  • pnpm 10 이상pnpm --version
  • Playwright 브라우저선택pnpm exec playwright install chromium
  • READMEREADME.md
운영체제

모든 단계가 표시된 상태입니다. 위에서 환경을 고르면 해당 단계만 남습니다.

가장 빠른 경로

  1. pnpm install
  2. pnpm forma init
  3. pnpm forma render forma.spec.json --out out

1저장소를 받고 의존성을 설치한다

Forma는 아직 npm에 배포되지 않았다. 저장소를 받아서 로컬에서 쓴다.

터미널 · unix

git clone https://github.com/dotoricode/forma.git
cd forma
pnpm install

PowerShell · win

git clone https://github.com/dotoricode/forma.git; cd forma; pnpm install

이렇게 보이면 성공

node_modules/ 가 생기고 설치 오류가 없다.

실패하면: pnpm이 없으면 corepack enable 을 먼저 실행한다.

2스펙 뼈대를 만든다

forma init이 완결된 리포트 뼈대를 하나 써준다. 두 블록짜리 스케치가 아니라 계약을 충족하는 최소 문서다.

저장소 루트

pnpm forma init

이렇게 보이면 성공

현재 디렉터리에 forma.spec.json 이 생긴다.

확인 방법

cat forma.spec.json 으로 열어보면 version이 0.2이고 sections에 6개 블록이 있다.

3내용을 채우고 검증한다

placeholder 문구를 실제 내용으로 바꾼다. 각 블록이 어떤 자리를 차지하는지는 placeholder가 그대로 말해준다. 다 쓰면 검증한다.

  1. cover 블록의 title을 실제 문서 제목으로
  2. narrative의 question과 summary를 채운다
  3. finding, recommendation, actions를 실제 내용으로

저장소 루트

pnpm forma validate forma.spec.json

이렇게 보이면 성공

`forma: <path> is a valid Forma spec` 이 출력된다.

실패하면: 실패 메시지가 어떤 역할이 비었는지 지목한다. 예를 들어 권고가 없으면 recommendation 역할이 비었다고 나온다.

여기까지 확인

  • forma.spec.json 이 검증을 통과한다
  • narrative.question 이 실제 질문 문장이다
  • verified로 표시한 블록마다 sourceRefs가 있다

하나라도 아니라면: 검증 메시지의 코드를 보고 해당 블록을 고친다. verified-claim-without-evidence 는 근거 없는 단정을 막는 규칙이다.

4렌더한다

검증을 통과한 스펙만 렌더된다. 결과는 폰트까지 포함된 단일 HTML이다.

저장소 루트

pnpm forma render forma.spec.json --out out

이렇게 보이면 성공

out/index.html 이 생기고 바이트 수가 출력된다. 대개 150~190KB 사이인데 7할이 임베딩된 폰트다.

확인 방법

브라우저로 out/index.html 을 열고 개발자 도구 Network 탭에서 요청이 0건인지 본다.

다음에 무엇을 볼까?

어떤 블록을 쓸 수 있는지 알고 싶다
블록 목록과 각 블록의 용도를 본다
결과물이 계속 리포트처럼만 나온다
meta.artifact를 manual이나 dashboard로 바꾼다

0.2 이상

0.1 스펙도 그대로 렌더된다. 읽을 때 자동 변환되고 계약 검사는 면제된다.

안 될 때

forma validate 가 unfilled-role 로 실패한다

원인 artifact마다 반드시 채워야 하는 의미 역할이 있다.

해결 메시지가 지목한 역할을 채울 블록을 넣는다. report의 recommendation 역할은 decision이나 recommendation 블록이 채운다.

한글이 네모로 보인다

원인 폰트 subset이 문서에 실제로 쓰인 글자만 담는다.

해결 렌더를 다시 돌린다. 스펙을 고치고 예전 HTML을 그대로 열면 새 글자가 폰트에 없다.

verified-claim-without-evidence 로 막힌다

원인 confidence를 verified로 적었는데 인용한 출처가 없다.

해결 sourceRefs나 evidenceRefs를 채우거나, 근거가 없다면 inferred로 바꾼다.

완료 확인

pnpm forma render forma.spec.json --out out && open out/index.html

이렇게 보이면 성공 브라우저에 문서가 뜨고, 콘솔 오류와 네트워크 요청이 모두 0이다.

다음에 할 것

  • artifact를 manual로 바꿔 절차 문서 만들기같은 내용도 구조와 읽는 순서가 달라진다
  • pnpm qa 로 4개 뷰포트 검사 돌리기접근성과 가로 오버플로를 자동으로 잡는다
