SDK 4.2.0을 Android 17에 출시해도 되는가?

기능 검증은 통과했지만 blocker 3건이 남아 있다. 사내 배포는 지금 진행하고, 정식 인증은 blocker 해결 후로 미루는 것을 권고한다.

  • 124건 중 118건 통과, 실패 6건 가운데 3건이 출시 blocker
  • blocker 3건 모두 Android 17의 백그라운드 실행 제한 변경에서 파생
  • 단말 커버리지가 상위 5개 기종에 몰려 있어 실패가 더 있을 수 있다

기능은 준비됐지만 정식 인증을 지금 받으면 백그라운드 제한 관련 blocker가 그대로 고객에게 나간다.추정

사내 배포와 정식 인증을 분리하면 일정 손실 없이 위험만 걷어낼 수 있다.

핵심 요약확인됨

Android 17 대응 작업은 4주간 진행됐고 기능 검증은 사실상 끝났다. 남은 실패 6건 중 3건은 백그라운드 실행 제한이 강화되면서 기존 재연결 로직이 깨진 것으로, 우회가 아니라 구조 수정이 필요하다.

나머지 3건은 테스트 환경 문제로 확인됐다.

확인됨

Android 17은 foregroundServiceType 없이 시작한 서비스를 화면 꺼짐 후 약 30초에 종료한다. 현재 재연결 스케줄러가 그 서비스에 얹혀 있어 세션이 끊기면 다시 붙지 못한다. 사용자에게는 조용한 연결 실패로 보인다.

권고추정

사내 배포는 이번 주 진행하고, 정식 인증은 blocker 3건 해결 후로 미룬다.

blocker는 전부 한 원인에서 나왔고 수정 범위가 재연결 스케줄러 한 곳으로 좁다. 1주면 해결 가능하다고 보며, 그동안 사내 배포로 실제 사용 데이터를 더 모을 수 있다.

이 판단이 바뀌는 조건

  • blocker 수정이 1주를 넘기면 커버리지 확대를 먼저 진행한다
  • 사내 배포에서 다른 원인의 연결 실패가 나오면 전면 보류로 전환한다
